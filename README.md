# 크리에이터 매칭 추천 프로토타입

**[🔗 데모 바로가기](https://creator-matching-prototype.vercel.app)** — 로그인 없이 접속 가능한 Vercel 프로덕션 배포입니다. `main` 브랜치에 push하면 자동으로 재배포됩니다.

광고주가 **예산·카테고리·팔로워 규모**를 입력하면 조건에 맞는 크리에이터를 추천하고, 조회수·참여율·협업 이력·비용 대비 조회 지표를 비교하는 웹 프로토타입입니다.

추천의 목적은 **광고주가 적합한 후보를 빠르게 추려 다음 협업 검토로 넘어가도록 돕는 것**입니다. 평균 조회수를 우선하고 참여율과 협업 이력으로 순위를 보완합니다.

> 문서 상태: 1차 구현 완료. 아래 실행 명령과 수치는 실제로 실행·검증했습니다. 검증 범위와 한계는 [AI_USAGE.md](AI_USAGE.md)에 기록되어 있습니다.

## 시작하기

### 구현 기준

- 브라우저에서 동작하는 클라이언트 전용 앱 (React 19 + TypeScript + Vite 8)
- 검증 환경: Node.js v25.6.0, npm 11.8.0
- 제공 데이터: `dummy_creators.csv` 200행, 11열. 원본은 저장소 루트에 그대로 두고, 앱이 fetch로 읽는 `public/data/dummy_creators.csv`에 동일 바이트로 복사했습니다 (SHA-256 해시 일치 확인).
- 별도 서버·DB·LLM API·API 키 없이 추천 계산

### 로컬 실행

저장소의 프로젝트 루트에서 실행합니다.

```bash
npm install
npm run dev
```

실행 후 터미널에 출력된 로컬 주소(예: `http://localhost:5173`)를 브라우저에서 엽니다. 포트 번호는 실행 환경에 따라 달라질 수 있습니다.

```bash
npm run build     # tsc -b && vite build — 검증 완료
npm run preview   # 빌드 결과 로컬 확인
npm run test      # vitest — 핵심 로직 41개 테스트, 검증 완료
npm run lint      # oxlint
```

CSV는 `public/data/dummy_creators.csv`에서 fetch로 읽습니다. 저장소 루트의 `dummy_creators.csv` 원본은 수정하지 않았으며, 두 파일의 SHA-256 해시가 동일함을 확인했습니다.

### 배포

Vercel 프로젝트 `creator-matching-prototype`(Vercel 기본 도메인, 커스텀 도메인 미구매)이 이 저장소의 GitHub `main` 브랜치에 연결되어 있어, push할 때마다 자동으로 재배포됩니다. 빌드 설정은 저장소 루트의 [`vercel.json`](vercel.json)에 명시되어 있습니다(`framework: vite`, `buildCommand: npm run build`, `outputDirectory: dist`) — Vite 프로젝트인데도 `public/` 디렉터리가 있어 자동 감지 시 출력 경로가 `dist`가 아닌 `public`으로 잘못 잡히는 문제를 이 설정으로 방지했습니다. 평가자가 로그인 없이 접속할 수 있도록 Vercel 배포 보호(SSO Protection)는 비활성화했습니다.

## 사용 흐름

1. 크리에이터 **1명과 1회 협업하는 예산 상한**을 원 단위로 입력합니다. 직접 입력하거나, ‘+10만 원’·‘+100만 원’·‘+1,000만 원’ 버튼으로 현재 금액에 더할 수 있습니다(1,000만 원은 증가 단위이며 입력 상한이 아닙니다). ‘금액 지우기’로 예산 필드만 비울 수 있습니다.
2. 카테고리를 1개 이상 선택하고 팔로워 규모를 1개 선택합니다.
3. ‘추천 보기’를 눌러 결과를 확인합니다. 결과는 **예산 기준 후보**와 **견적 확인 필요** 두 탭으로 나뉘며, 각 탭 이름에 건수가 항상 표시됩니다. 기본 탭은 예산 기준 후보입니다.
4. 예산 기준 후보 탭 안에서 조회수·참여율·협업점수·참고 비용 기준으로 재정렬할 수 있습니다. 각 탭은 10명씩 페이지네이션됩니다.
5. 예산 기준 후보가 0명이어도 탭은 유지되며, 조건 완화 대안과 함께(견적 확인 후보가 있으면) ‘견적 확인 필요 후보 N명 보기’ 버튼으로 바로 이동할 수 있습니다.

입력 예산은 여러 크리에이터에게 배분할 총예산이 아닙니다. 과거 평균 집행액이 예산 이하인 후보를 찾으며, 실제 계약 가격과 협업 가능 여부는 별도 확인이 필요합니다.

## 추천 로직

### 1. 조건 충족 여부와 추천 순위를 분리합니다

카테고리와 팔로워 규모로 후보를 추린 뒤, 이력 보유 후보에 `과거 평균 집행액 ≤ 입력 예산`을 적용합니다. 카테고리는 선택 항목 중 하나라도 일치하면 포함하는 OR 조건입니다.

| 규모 | 팔로워 범위 |
| --- | --- |
| 나노 | 0 이상 ~ 10,000 미만 |
| 마이크로 | 10,000 이상 ~ 100,000 미만 |
| 매크로 | 100,000 이상 |

이 구간은 본 프로토타입에서 정한 기준입니다. 팔로워 수는 규모 필터에 사용하고 추천 점수에 다시 가점하지 않습니다. 누적 집행액도 예산 필터와 점수에 사용하지 않습니다.

### 2. 도달 > 반응 > 협업 이력 순으로 평가합니다

```text
추천 점수 S = 0.60 × V + 0.25 × E + 0.15 × C

V: 동일 규모 내 평균 조회수 백분위 점수
E: 동일 규모 내 참여율 백분위 점수
C: 협업 점수
```

60:25:15는 도달을 우선한다는 제품 목적에 따른 초기 가설입니다. 학습된 최적 가중치나 광고 성과의 확률이 아닙니다. 가중합이므로 평균 조회수 내림차순과 동일하지 않습니다.

조회수와 참여율은 동일 팔로워 규모의 유효 데이터 전체를 기준으로 0~100점 백분위로 변환합니다. 신규·예산 초과 후보도 이 기준 집합에는 포함합니다. 따라서 예산이나 카테고리를 바꿔도 같은 후보의 점수가 바뀌지 않습니다.

```text
N = 동일 규모의 유효 후보 수
L = 해당 값보다 작은 값의 개수
T = 해당 값과 같은 값의 개수

백분위 점수 = 100 × (L + (T - 1) / 2) / (N - 1)
N = 1이면 50점
```

동일한 값에는 동일 점수를 부여합니다. 모든 값이 같으면 50점입니다. 규모별 상대점수이므로 나노 80점과 매크로 80점의 도달량이 같다는 뜻은 아닙니다.

### 3. 평점과 집행 경험으로 협업 점수를 만듭니다

```text
R = 광고주 평점 / 5 × 100
M = 전체 유효 데이터의 최대 캠페인 집행 건수
H = 100 × ln(1 + 집행 건수) / ln(1 + M)
C = 0.70 × R + 0.30 × H
```

M이 0이면 H는 0입니다. 제공 데이터의 M은 30입니다. 평점은 5점 만점이라는 구현 가정이며 실제 연동 전 확인해야 합니다.

평점은 협업 만족도, 집행 건수는 경험을 나타내는 보조 지표로 사용합니다. 경험이 증가할수록 추가 가점 효과가 줄도록 로그 변환합니다. 집행 건수를 평점 응답 수로 간주하지 않으며, 이 계산을 통계적 신뢰도 보정이라고 설명하지 않습니다.

가격과 집행 이력은 유효하지만 평점만 미확인인 후보는 평점 부분에 50점을 적용하고 ‘평점 미확인’을 표시합니다. 이 방어 사례는 현재 제공 데이터에는 없습니다. 캠페인 이력이 없는 신규 후보에는 이 대체 규칙을 적용하지 않습니다.

### 4. 비용 효율은 별도로 비교합니다

```text
참고 1천 조회당 비용 = 과거 평균 집행액 / 평균 조회수 × 1,000
```

양의 집행액과 조회수가 있는 이력 보유 후보만 계산합니다. 신규 후보나 조회수 0인 후보는 ‘계산 불가’이며, 비용순 정렬에서는 마지막에 표시합니다.

기본 추천 점수에 이 지표를 추가하면 조회수가 중복 반영되고 저가 후보를 과도하게 선호할 수 있어, 별도 표시·정렬로 제공합니다. 광고주가 도달과 비용 효율의 차이를 직접 비교할 수 있도록 한 결정입니다.

이 지표는 **실제 광고 CPM이 아닙니다.** 평균 집행액과 평균 조회수가 같은 광고 캠페인에서 측정되었는지 확인할 수 없으므로 참고값으로만 사용합니다.

### 5. 신규 후보를 무료 또는 저평점 후보로 처리하지 않습니다

제공 CSV에는 캠페인 이력이 없고 평점이 공란인 후보가 27명 있습니다. 이들의 평균·누적 집행액 0원은 무료 견적을 의미하지 않습니다.

- 카테고리·규모가 맞으면 ‘견적 확인 필요’ 탭에 표시합니다.
- 예산 이하 후보 수에는 포함하지 않습니다.
- 가격은 ‘가격 미확인’, 평점은 ‘평가 없음’으로 표시합니다.
- 신규 탭은 `(0.60 × V + 0.25 × E) / 0.85`로 내부 정렬합니다.
- 이 내부 점수는 기존 후보의 종합점수와 비교하는 숫자로 노출하지 않습니다.
- 예산 기준 탭의 정렬 컨트롤은 신규 탭에 적용하지 않습니다.

### 6. 결과 0건에서는 검증 가능한 대안을 제공합니다

기존 후보가 0명이면 현재 카테고리·규모의 최소 평균 집행액을 계산해 예산 변경을 제안합니다. 현재 카테고리·예산을 유지하고 다른 규모를 선택했을 때 후보가 나오는지도 각각 계산합니다.

후보가 실제로 1명 이상 나오는 대안만 표시합니다. 사용자가 클릭한 경우 해당 조건 하나만 바꾸고 재검색합니다. 카테고리를 자동으로 확장하거나 예산을 조용히 변경하지 않습니다. 신규 후보만 있는 경우에도 기존 후보 0건 안내와 대안을 유지합니다.

### 정렬의 재현성

기본 동점 해소는 추천 점수 내림차순 → 평균 조회수 내림차순 → 과거 평균 집행액 오름차순 → ID 사전순입니다. 다른 정렬은 선택 지표를 먼저 적용한 후 기본 기준으로 동점을 해소합니다. 내부 점수를 반올림하지 않고 표시할 때만 소수 둘째 자리까지 반올림합니다.

## 데이터와 예외 처리

원본 CSV를 보존하고 파싱된 메모리 객체에서 전처리합니다. UTF-8 BOM, CRLF, 인용부호를 지원하는 파서를 사용합니다. 공란 평점을 자동으로 0으로 바꾸지 않습니다.

필수 헤더 누락·파싱 실패·ID 중복은 파일 수준 오류로 처리합니다. 잘못된 필수 숫자나 이력 불일치 행은 사유를 기록하고 제외합니다. 일부 행 제외는 경고로 알리고 유효 행이 없으면 데이터 오류로 처리합니다. 정상 신규 27명은 오류가 아닙니다.

입력 오류, 파일 오류, 정상 검색 결과 0건은 서로 다른 상태로 표시합니다. 전체 데이터 계약과 예외 규칙은 [PRD.md](PRD.md)의 5절을 따릅니다.

## 대표 검증 시나리오

아래는 제공 CSV에 설계 수식을 적용한 기준값이며, `npm run test`의 vitest 스위트(`src/lib/__tests__/search.test.ts`, `pagination.test.ts`)가 실제 구현으로 이 값들을 재현하는지 자동 검증합니다.

| 조건 | 기대 결과 |
| --- | --- |
| 뷰티·패션 / 마이크로 / 200만 원 | 기존 21명, 견적 확인 필요 3명 |
| 위 조건의 추천 상위 3명 | C0077 78.19점 → C0175 67.59점 → C0066 67.24점 |
| 식품 / 나노 / 50만 원 | 기존 2명, 견적 확인 필요 2명. 기존 순서 C0091 → C0166 |
| 피트니스 / 매크로 / 50만 원 | 기존·신규 모두 0명 |
| 위 빈 결과의 예산 대안 | 동일 카테고리·규모 최소 평균 집행액 593만 원 |
| 위 빈 결과의 마이크로 대안 | 50만 원 이내 기존 후보 0명이므로 제안하지 않음 |
| C0077 참고 비용 | 780,000 / 35,172 × 1,000 ≈ 22,177원 |

뷰티·패션 / 마이크로 / 200만 원 사례에서 가중치를 70:20:10으로 변경하면 상위 3명이 유지되고 4·5위가 바뀌었습니다. 50:30:20에서는 2·3위가 바뀌고 상위 5명 중 1명이 교체되었습니다. 이는 제한된 사례의 민감도 확인이며 전반적인 추천 품질을 입증하지 않습니다.

구현 검증은 위 사례 외에도 규모·예산 경계, 카테고리 OR, 신규 구분, 점수 불변성, 동점 정렬, 0으로 나누기, 대안 건수 일치, 원본 CSV 해시 불변을 포함합니다. 탭·페이지네이션 도입 이후에는 전체 정렬 결과를 페이지 단위로 이어 붙였을 때 원본과 정확히 일치하는지(중복·누락 없음), 정렬 옵션을 바꿔도 후보 집합과 개별 점수가 그대로인지, 예산 기준 탭과 견적 확인 탭 사이에 후보 ID가 겹치지 않는지도 검증합니다. 상세 수용 기준 15개는 [PRD.md](PRD.md)의 9절에 있습니다. 원본에 없는 오류 케이스는 별도 fixture로 검증합니다.

## 설계의 트레이드오프와 한계

| 선택 | 얻는 점 | 한계 |
| --- | --- | --- |
| 규칙 기반 추천 | 설명 가능하고 같은 입력에서 결과 재현 가능 | 실제 집행 성과로 학습한 모델은 아님 |
| 규모별 백분위 | 단위 차이와 극단값의 영향을 줄임 | 조회수의 절대 배수 차이를 보존하지 못함 |
| 도달 중심 가중합 | 조회수 우선 목적에 반응·협업 정보를 보완 | 가중치는 초기 가설이며 절대 조회수순은 아님 |
| 과거 평균액으로 예산 필터 | 보유 데이터로 후보를 좁힐 수 있음 | 현재 견적·세금·사용권·제작 범위를 확정하지 못함 |
| 신규 후보 별도 탭 | 가격·평점을 오해하지 않고 후보를 유지하며, 탭 건수와 바로가기 버튼으로 접근성을 확보 | 기본 탭이 아니므로 한 번의 추가 클릭이 필요 |
| 비용 지표 별도 정렬 | 도달과 비용 효율을 사용자가 구분해 비교 | 실제 CPM이나 성과 예측값으로 사용할 수 없음 |

평균 조회수는 순도달 인원이나 광고 콘텐츠의 예상 조회수가 아닙니다. 참여율 분모와 플랫폼별 집계 기준이 명시되지 않아 `조회수 × 참여율`을 예상 반응수로 계산하지 않습니다. 플랫폼별 측정 차이, 오디언스 중복, 타깃 적합성, 콘텐츠 품질과 브랜드 안전성도 현재 데이터로 보정하지 않습니다.

## 비즈니스 관점과 제외 범위

가설은 후보 탐색·비교 시간을 줄여 협업 검토 진입과 운영 효율을 높이는 것입니다. 프로토타입에서는 후보 선정 시간과 추천 근거 이해도를 확인하고, 상용화 이후 견적 요청률·계약 전환율·캠페인별 운영 시간을 측정할 수 있습니다. 실제 개선 효과는 아직 측정하지 않았습니다.

MVP에서는 로그인, 실제 견적 요청·계약·결제, 다수 후보 예산 조합, 실시간 데이터 수집, 매출·ROAS 예측, 가중치 조절 UI를 제외합니다. 각 제외 이유는 [PRD.md](PRD.md)에 정의되어 있습니다.

## 남은 확인 사항

- 이번 세션에서도 브라우저 자동화 도구를 사용할 수 없어, 프로덕션 배포 역시 `curl`로 index.html·CSV 응답과 로그인 없는 접근성만 확인했습니다. 탭 전환, 페이지네이션, 예산 금액 추가/지우기 버튼, 뷰티·패션/마이크로/200만원(21/3명)과 피트니스/매크로/50만원(빈 결과+593만원 대안) 시나리오의 실제 클릭 동작은 배포된 것과 SHA-256이 동일한 로컬 빌드 산출물에 대해 vitest로 계산 결과를 검증했을 뿐, 실제 브라우저 클릭으로는 확인하지 못했습니다. [데모](https://creator-matching-prototype.vercel.app)에서 직접 확인해 주세요.
- `npm run lint` 실행 시 `useCreatorData.ts`의 데이터 로딩 이펙트에서 `set-state-in-effect` 경고가 1건 있습니다 (fetch 시작 시 로딩 상태로 동기 전환하는 통상적인 패턴이며 오류는 아닙니다).
- 과제 안내문 원문이나 개인 배경 핸드오프는 공개 저장소에 복사하지 않습니다.
